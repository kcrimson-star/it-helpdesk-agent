Executive Overview & System Architecture

An enterprise-grade, lightweight autonomous IT Helpdesk agent orchestrating real-time issue classification, automated root-cause hypothesis, ITIL priority calculations, and programmatic REST API ticket creation.

1. System Synopsis & Operational Objectives

NovaDesk AI bridges the gap between chaotic multi-channel employee support requests and enterprise ticketing management. Built with a minimalist footprint, the engine combines FastAPI high-throughput async REST microservices, LangChain Groq inference utilizing open-source frontier models (openai/gpt-oss-120b), an interactive Streamlit operations interface, and an embedded React 18 reactive triage board.

2. End-to-End Architectural Blueprint

➔

LPU Inference (Groq Cloud) openai/gpt-oss-120b (Ultra Low-Latency)
➔
Deterministic Heuristic Regex Fallback Engine (Offline Safe)
➔
Persistence (SQLite 3) Tickets • KB Articles • Audit Trails

3. Technology Stack & Component Matrix

Subsystem Technology Version Operational Responsibility

LLM Orchestration LangChain + LangChain-Groq 0.3.0 Prompt pipelining, schema validation, multi-turn context retention.
Inference Engine Groq LPU Cloud v1 API Sub-second token streaming using openai/gpt-oss-120b.
Frontend Presentation Streamlit 1.65.0 Interactive operations console, triage intake, ticket inspector.
Micro-Frontend React 18 + Babel Standalone 18.2.0 Real-time client-side incident radar and status toggle matrix.

4. Architectural Design Principles

Zero-Latency Fallback Guarantee
If external internet connectivity, Groq API quotas, or network policies block LLM execution, the agent instantly drops back to a built-in deterministic heuristic rule engine without dropping tickets.
Strict ITIL Alignment
Priorities (P1-P4) are evaluated by calculating operational Impact and Urgency matrices, establishing legally defensible SLA resolution deadlines (1h to 48h).

AI Triage & Agent Intelligence Engine

Deep dive into the LangChain-orchestrated prompt engineering, JSON schema enforcement, ITIL SLA calculation formulas, and deterministic heuristic fallback architectures.

1. Primary Inference Pipeline: openai/gpt-oss-120b

The triage engine targets openai/gpt-oss-120b hosted on Groq LPU hardware. This model delivers frontier-class reasoning capable of deciphering complex technical errors (e.g. Wi-Fi 802.1x handshake failures, Docker socket permission drops, TPM bitlocker traps) in under 750 milliseconds.

2. Dual-Stage Prompt & Guardrail Architecture

System Prompt Schema (Truncated): You are NovaDesk AI, an expert Principal IT Helpdesk Engineer with ITIL v4 certification. Analyze technical inquiries, accurately classify category, calculate SLA priority, identify root cause, and generate concrete step-by-step diagnostic actions with copy-paste terminal commands. Return strictly valid JSON with schema: { "title": string, "category": string, "sub_category": string, "priority": "Critical"|"High"|"Medium"|"Low", "urgency": string, "impact": string, "estimated_sla_hours": int, "assigned_department": string, "root_cause_hypothesis": string, "solutions": [string], "quick_commands": [string] }

3. ITIL Priority Calculation & SLA Matrix

Priority is mathematically derived from the intersection of organizational Impact (blast radius) and operational Urgency (business blockage):

Priority Level Impact / Urgency Trigger Target SLA Routing Department
Critical (P1) Company-wide outage, Security breach, Executive blocker 1 Hour Endpoint SecOps / NetOps Escaped Queue
High (P2) Departmental core process blocked, VPN Gateway failure 4 Hours Network Engineering / IAM Support
Medium (P3) Single user workflow blocked, workaround available 24 Hours Tier 1 Workstation Support
Low (P4) General inquiry, cosmetic peripheral bug, software request 48 Hours General IT Queue

4. Deterministic Heuristic Fallback Engine

In accordance with high-availability engineering, ITHelpDeskAgent.py and app/agent.py embed a rule-based expert system that activates when LLM inference fails:

Network & Gateway Filter
Detects: vpn, wifi, dns, timeout 502.
Categorizes: Network & Connectivity • Priority: High.
Output: ipconfig /flushdns, adapter restart.
Identity & Access Filter
Detects: mfa, okta, locked, password.
Categorizes: Identity & Access (IAM) • Priority: Medium.
Output: Device time-sync check, TAP issuance escalation.
Security & Drive Encryption
Detects: bitlocker, ransom, breach, bsod.
Categorizes: Security & Compliance • Priority: Critical.
Output: Isolate device, retrieve PCR recovery keys.
Hardware & Peripherals
Detects: dock, monitor, flicker, hdmi.
Categorizes: Hardware • Priority: Medium.
Output: Capacitor discharge, Win+Ctrl+Shift+B graphics reset.

FastAPI Backend & REST API Specification

Architectural contracts, asynchronous lifecycle handlers, endpoint routing tables, schema validators, and OpenAPI integration standards.

1. Service Lifecycle & Lifespan Handlers

The backend is implemented in app/main.py using FastAPI's modern @asynccontextmanager lifespan model. On startup, SQLite tables are verified and auto-migrated, knowledge base runbooks are verified, and CORS middleware is configured to allow decoupled micro-frontends.

2. Core REST API Endpoint Reference

Method URI Path Request Body / Params Primary Response Content
POST /api/classify TriageRequest (issue_description) Category, Priority, Root Cause, Step Solutions, Quick Commands.
POST /api/tickets TicketCreate (title, description, auto_diagnose) Created Ticket record (HD-XXXX), assigned queue, SLA timestamp.
GET /api/tickets Query: status, priority, category, search Array of Tickets, total count, pagination metadata.
GET /api/tickets/{id} Path: ticket_id (int) Detailed ticket object with timeline comments and diagnosis.
PATCH /api/tickets/{id} TicketUpdate (status, priority, assignee) Updated ticket record with modified state and timestamps.
POST /api/tickets/{id}/resolve Query: resolution_notes (string) Sets status to Resolved, appends resolution audit log.
GET /api/health None Database status, active LLM model, engine health.

The active queue stream is configured with Newest-First ordering (ORDER BY id DESC), guaranteeing that incoming inquiries (such as gaming GPU stutters or VPN drops) appear immediately at the top of the queue:

// Live Ticket Action & Dynamic State Trigger: def resolve_ticket_action(t_id: int): update_ticket(t_id, {"status": "Resolved", "resolution_notes": "Resolved via Command Center"}) st.rerun() # Instantly increments 'Resolved Today' (+1) and decrements 'New/In Progress' (-1) def reopen_ticket_action(t_id: int): update_ticket(t_id, {"status": "Open", "resolution_notes": ""}) st.rerun() # Automatically reverts counters and clears resolved_at timestamp

Data Layer & Knowledge Base Runbooks

Relational SQLite database schema design, entity relationship integrity, pre-seeded enterprise IT runbooks, and keyword relevance retrieval systems.

1. Relational Database Architecture: SQLite 3

Managed by app/database.py, the data layer utilizes a thread-safe SQLite connection factory with WAL (Write-Ahead Logging) mode enabled. This guarantees atomic transactions, sub-millisecond query execution, and complete isolation without external database overhead.

2. Database Schema Definitions

Table Name Primary Columns Foreign Keys & Constraints Operational Purpose
tickets id (PK), ticket_code (UNIQUE), title, description, category, priority, status, requester_name, requester_email, department, assigned_to, solutions (JSON), sla_deadline, created_at, resolved_at UNIQUE(ticket_code), INDEX on status, priority, category Core transactional record tracking all ingested support tickets and ITIL lifecycle states.
ticket_comments id (PK), ticket_id (INT), author_name, author_type ('agent' | 'user' | 'system'), content, created_at FOREIGN KEY(ticket_id) REFERENCES tickets(id) ON DELETE CASCADE Audit trail tracking engineer work notes, system status updates, and user communications.
kb_articles id (PK), title, category, tags (JSON), summary, content (Markdown), quick_commands (JSON), created_at INDEX on category, full-text token indexing Repository of standard operating procedures, verified runbooks, and self-service guides.

3. Pre-Seeded Enterprise Knowledge Base Runbooks

KB-01: GlobalProtect VPN Gateway Drops
Category: Network & Connectivity
Symptoms: Gateway connection timeout error 502, split-tunnel drops.
Standard Procedure: Flush DNS cache via ipconfig /flushdns; restart PanGPS service daemon; verify split-tunnel ICMP route gateway.
KB-02: Okta / Entra ID MFA Device Lost
Category: Identity & Access (IAM)
Symptoms: Push notification timeout, new phone authentication block.
Standard Procedure: Verify automatic device network time sync; clear active session cookies; issue a 24-hour Temporary Access Pass (TAP) upon video identity verification.
KB-03: BitLocker Drive Encryption Prompt
Category: Security & Compliance
Symptoms: Blue BitLocker recovery key screen after firmware/BIOS update.
Standard Procedure: Retrieve 48-digit numerical key via Microsoft Intune portal; halt power-cycling to prevent TPM hardware lockout timer; rebind PCR registers.
KB-04: Outlook OST Cache Corruption
Category: Email & Collaboration
Symptoms: Calendar sync stalls, inbox freezing, Send/Receive errors.
Standard Procedure: Launch Outlook in safe mode (outlook.exe /safe); rename stale .ost container to trigger cloud rebuild.

3. Operations Troubleshooting & Diagnostic Guide

Observed Symptom Root Cause Hypothesis Standard Remediation Procedure
Port 8000 Address in Use Stale uvicorn process bound to port Execute fuser -k 8000/tcp or kill existing task via task manager.
Groq Rate Limit (429) Token burst quota reached on free tier System automatically switches to fallback model or deterministic heuristics.
SQLite Database Locked High concurrent write saturation WAL mode ensures concurrency; verify permissions on data/helpdesk.db.
React Component Blank Restricted iframe or CDN block Ensure unpkg CDN access is permitted for React 18 and Babel scripts.
